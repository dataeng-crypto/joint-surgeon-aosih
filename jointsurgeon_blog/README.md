# JointSurgeon Daily Blog Engine

This package is the canonical implementation for research contracts, quality control,
CMS submission, public verification, interlinking, and sitemap handling. Dated
`output/daily-blog/*/publish_blog.py` files are historical artifacts and must not be
imported or copied for future runs.

## Safety model

- A daily run may publish zero or one new record.
- Publication is blocked unless normal browsers, Googlebot mobile/desktop, Bingbot,
  and AdsBot receive materially equivalent legitimate content and XML sitemaps.
- A second read-only preflight requires a correct server-rendered article H1/byline/date,
  exact non-slash canonicals, complete archive coverage, and truthful sitemap lastmod.
- `SKIPPED_NO_QUALITY_TOPIC` and `FAILED_QC` perform no CMS, sitemap, or GSC writes.
- The publication threshold is 80 after every hard gate passes.
- Candidate scores require retained evidence, an India market scope, India-patient and
  conversion-fit floors, and a validated primary service route. The new-record runner
  accepts only `editorialAction=NEW`; refresh/consolidation is a separate workflow.
- A fresh complete archive package must cover every CMS record, public final URL, body,
  and eight-part patient-intent fingerprint before selection or publication.
- The body is an HTML fragment with no H1 and no JSON-LD.
- The body starts with an unheaded 2-3 paragraph answer, then uses 4-9 H2 sections
  and optional H3 subsections. Summary, CTA, and disclaimer sections stay unheaded.
- Editorial-layout QC rejects fragmented headings, paragraphs over 110 words, lists
  outside 2-7 items, repeated CTA links, decorative separators, and non-semantic tables.
- Head tags and one combined JSON-LD graph are generated by `schema.py`.
- Every PubMed and non-PubMed ledger source is freshly fetched with `verify-evidence`;
  final domain, content hash, source freshness, conservative support proposition, exact
  visible claim binding, and adjacent citation are hard gates.
- Exactly one cover contract with a verified JointSurgeon HTTPS public URL is required,
  so final OG, Twitter, and ImageObject metadata exists before CMS creation.
- Draft-declared link and tag values never satisfy QC by themselves; validation requires
  current retained live-route and CMS-tag catalogs.
- GSC URL Inspection remains visible-browser-only and is intentionally not implemented
  as an HTTP client.
- CMS credentials have no source fallback. `CMS_EMAIL` and `CMS_PASSWORD` must be
  supplied by a protected runtime secret source; absence fails before any CMS request.
- Durable idempotency state, a cross-process lock, one-create budget, slug lookup,
  record ID, exact readback, cover URL, mutation journal, and resume checkpoints prevent
  duplicate creates after ambiguous or partial CMS outcomes.

## Commands

Set the bundled dependencies when CMS work is required:

```powershell
$env:PYTHONPATH = "$PWD\tmp\pydeps"
```

Run the mandatory read-only release preflight first:

```powershell
python -m jointsurgeon_blog.runner preflight `
  --output-dir output\daily-blog\YYYY-MM-DD-preflight
```

Any `BLOCKED_SITE_PREFLIGHT` or `BLOCKED_TECHNICAL_PREFLIGHT` result stops the run with
zero CMS, inbound-link, sitemap-generator, or GSC mutations.

After a passing preflight and credential rotation, build the complete read-only archive:

```powershell
python -m jointsurgeon_blog.runner build-archive --output archive-package.json
```

Validate one draft without external mutation:

```powershell
python -m jointsurgeon_blog.runner validate `
  --draft output\daily-blog\YYYY-MM-DD-slug\draft.json `
  --output-dir output\daily-blog\YYYY-MM-DD-slug `
  --archive-package archive-package.json `
  --link-catalog output\daily-blog\YYYY-MM-DD-slug\link-catalog.json `
  --tag-catalog output\daily-blog\YYYY-MM-DD-slug\tag-catalog.json
```

Select the highest-quality candidate or return `SKIPPED_NO_QUALITY_TOPIC`:

```powershell
python -m jointsurgeon_blog.runner select `
  --candidate candidate-a.json `
  --candidate candidate-b.json `
  --output-dir output\daily-blog\YYYY-MM-DD-selection `
  --archive-package archive-package.json `
  --link-catalog link-catalog.json `
  --tag-catalog tag-catalog.json
```

Verify every ledger source:

```powershell
python -m jointsurgeon_blog.runner verify-evidence `
  --draft draft.json `
  --output evidence-verification.json `
  --verified-draft draft.verified.json
```

Build the read-only live catalogs before candidate validation:

```powershell
python -m jointsurgeon_blog.runner build-link-catalog --output link-catalog.json
python -m jointsurgeon_blog.runner build-tag-catalog --output tag-catalog.json
```

Publish exactly one QC-passed draft:

```powershell
python -m jointsurgeon_blog.runner publish `
  --draft draft.json `
  --output-dir output\daily-blog\YYYY-MM-DD-slug `
  --archive-package archive-package.json `
  --link-catalog link-catalog.json `
  --tag-catalog tag-catalog.json `
  --cover cover.jpg
```

Run the historical 14 August regression fixture:

```powershell
python -m jointsurgeon_blog.runner regression-20260814 `
  --body output\daily-blog\2026-08-14-fast-bowler-shoulder-pain-treatment-jaipur\body.html `
  --output output\automation-upgrade-2026-08-14\regression-20260814.json
```

## Terminal statuses

- `PUBLISHED`
- `SKIPPED_NO_QUALITY_TOPIC`
- `FAILED_QC`
- `DRAFT_ONLY`
- `FAILED_PUBLISH`
- `BLOCKED_SITE_PREFLIGHT`
- `BLOCKED_TECHNICAL_PREFLIGHT`
- `BLOCKED_ARCHIVE_INCOMPLETE`
- `FAILED_EVIDENCE_VERIFICATION`
- `BLOCKED_RUN_LOCKED`
- `BLOCKED_COMMIT_STATE_UNKNOWN`
- `CMS_COMMITTED_READBACK_BLOCKED`
- `CMS_COMMITTED_PUBLIC_QA_BLOCKED`
- `PUBLISHED_SITEMAP_BLOCKED`
- `PUBLISHED_POSTFLIGHT_BLOCKED`
- `GSC_INDEXING_BLOCKED`
- `PUBLISHED_INTERLINK_BLOCKED`

`Indexing requested` means the request was accepted into Google's crawl queue. It does
not mean the URL is indexed.
